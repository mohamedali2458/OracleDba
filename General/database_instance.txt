𝐔𝐧𝐝𝐞𝐫𝐬𝐭𝐚𝐧𝐝𝐢𝐧𝐠 𝐭𝐡𝐞 𝐃𝐢𝐟𝐟𝐞𝐫𝐞𝐧𝐜𝐞 𝐁𝐞𝐭𝐰𝐞𝐞𝐧 𝐃𝐚𝐭𝐚𝐛𝐚𝐬𝐞 𝐚𝐧𝐝 𝐈𝐧𝐬𝐭𝐚𝐧𝐜𝐞 𝐢𝐧 𝐎𝐫𝐚𝐜𝐥𝐞

One of the most important core concepts for any DBA is understanding the difference between a 𝐃𝐚𝐭𝐚𝐛𝐚𝐬𝐞 and a 𝐃𝐚𝐭𝐚𝐛𝐚𝐬𝐞 𝐈𝐧𝐬𝐭𝐚𝐧𝐜𝐞 in the Oracle environment.

 𝐖𝐡𝐚𝐭 𝐢𝐬 𝐚 𝐃𝐚𝐭𝐚𝐛𝐚𝐬𝐞?

In Oracle Database, the 𝐃𝐚𝐭𝐚𝐛𝐚𝐬𝐞 is:

✔ A collection of physical files
✔ Stored on disk
✔ Contains actual data

Main types of database files:

* Datafiles
* Control files
* Redo log files
* Archived redo logs
* Backup files
* Parameter file (PFILE/SPFILE)
* Password file
* Alert log file
* Trace files

👉 Database = Physical (Stored on Disk)

 𝐖𝐡𝐚𝐭 𝐢𝐬 𝐚𝐧 𝐈𝐧𝐬𝐭𝐚𝐧𝐜𝐞?

An 𝐎𝐫𝐚𝐜𝐥𝐞 𝐈𝐧𝐬𝐭𝐚𝐧𝐜𝐞 is:

✔ Memory structures
✔ Background & server processes
✔ Loaded into RAM when the database starts

It consists of:

 𝐌𝐞𝐦𝐨𝐫𝐲

 𝗦𝗚𝗔 (System Global Area)
 𝗣𝗚𝗔 (Program Global Area)

𝐏𝐫𝐨𝐜𝐞𝐬𝐬𝐞𝐬

𝗕𝗮𝗰𝗸𝗴𝗿𝗼𝘂𝗻𝗱 𝗽𝗿𝗼𝗰𝗲𝘀𝘀𝗲𝘀 (𝗗𝗕𝗪𝗻, 𝗟𝗚𝗪𝗥, 𝗦𝗠𝗢𝗡, 𝗣𝗠𝗢𝗡, 𝗲𝘁𝗰.)
𝗦𝗲𝗿𝘃𝗲𝗿 𝗽𝗿𝗼𝗰𝗲𝘀𝘀𝗲𝘀

Instance = Memory + Processes
Instance exists only in RAM

 Very Important Points

✔ Every running database has at least one instance
✔ Instance can exist without opening a database (NOMOUNT state)
✔ Database files can exist on disk without an active instance

🔥 Losing Instance → No big issue (restart possible)
❌ Losing Datafiles → Database loss

Simple Example (Best Way to Understand)

Think of:

Microsoft Word = Instance
Word Document = Database

You use Word (instance) to read the document (database).

If Word crashes → You reopen it.
If document is deleted → Data is gone.

 𝐎𝐫𝐚𝐜𝐥𝐞 𝐀𝐫𝐜𝐡𝐢𝐭𝐞𝐜𝐭𝐮𝐫𝐞 𝐂𝐨𝐧𝐟𝐢𝐠𝐮𝐫𝐚𝐭𝐢𝐨𝐧𝐬

𝟏 𝐒𝐢𝐧𝐠𝐥𝐞 𝐈𝐧𝐬𝐭𝐚𝐧𝐜𝐞

  1 Database ↔ 1 Instance (Most common)

𝟐 𝐌𝐮𝐥𝐭𝐢𝐩𝐥𝐞 𝐒𝐢𝐧𝐠𝐥𝐞 𝐈𝐧𝐬𝐭𝐚𝐧𝐜𝐞𝐬 𝐨𝐧 𝐒𝐚𝐦𝐞 𝐒𝐞𝐫𝐯𝐞𝐫

Multiple databases running separately.

𝟑 𝐎𝐫𝐚𝐜𝐥𝐞 𝐑𝐀𝐂 (𝐑𝐞𝐚𝐥 𝐀𝐩𝐩𝐥𝐢𝐜𝐚𝐭𝐢𝐨𝐧 𝐂𝐥𝐮𝐬𝐭𝐞𝐫𝐬)

Multiple instances accessing one database.
Provides High Availability & Scalability.
